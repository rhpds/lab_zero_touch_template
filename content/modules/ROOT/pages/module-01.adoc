= Overview

This template is the starting point for all RHDP zerotouch labs.
It provides the directory structure, configuration files, and example scripts that the platform expects.
Work through these modules in order to build and deploy your own lab.

== First things to change in your new repository

Before writing any content, update these four values so the lab is yours:

[cols="1,2,2"]
|===
| File | Field | What to set

| `site.yml`
| `title:`
| Your lab's display title

| `site.yml`
| `url:`
| Your GitHub repo URL (e.g. `https://github.com/your-org/your-lab`)

| `site.yml`
| `start_page:`
| `modules::module-01.adoc` — update if you rename your first page

| `content/antora.yml`
| `title:`
| Your lab title (shown in Antora navigation)
|===

[IMPORTANT]
====
`content/antora.yml` has a `name:` field (default: `modules`).
This value must exactly match `antora.name` in `ui-config.yml`.
Do not change `name:` in `antora.yml` unless you change both files together.
====

== Directory structure

[source,shell]
----
.
├── site.yml                    # Antora playbook — title, url, start_page, attributes
├── ui-config.yml               # Module list and tab definitions for the lab UI
├── config/
│   ├── instances.yaml          # VM definitions (image, memory, AnsibleGroup)
│   ├── networks.yaml           # Network attachment definitions (NADs)
│   └── firewall.yaml           # NetworkPolicy rules (additive to platform defaults)
├── content/
│   ├── antora.yml              # Antora component descriptor (name: must match ui-config.yml)
│   └── modules/ROOT/
│       ├── assets/images/      # Images referenced in your .adoc pages
│       └── pages/              # Your lab instruction pages (one .adoc per module)
├── setup-automation/
│   ├── main.yml                # Ansible playbook — runs once at provisioning time
│   ├── setup-host1.sh          # Provisioning script for the host1 VM
│   └── ansible.cfg
├── runtime-automation/
│   ├── main.yml                # Ansible playbook — runs on each UI action
│   ├── module-NN/              # One directory per module (setup/solve/validation scripts)
│   └── ansible.cfg
└── utilities/
    ├── lab-build               # Build Antora site + extract nookbag UI into ./www/
    ├── lab-serve               # Start local HTTP server on http://localhost:8080
    ├── lab-clean               # Remove ./www/* (clears previous build)
    ├── lab-stop                # Stop the local HTTP server container
    └── lab-check-updates       # Check nookbag SPA and nookbag-bundle for newer releases
----

== Local preview

=== Prerequisites

[cols="1,3"]
|===
| Requirement | Notes

| `podman` or `docker`
| `podman` is preferred and detected automatically. Pre-installed on RHEL/Fedora. On macOS, install https://podman-desktop.io[Podman Desktop] or Docker Desktop.

| `wget`
| Downloads the nookbag UI on first run. Pre-installed on RHEL/Fedora. On macOS: `brew install wget`.

| `unzip`
| Extracts the nookbag UI zip. Pre-installed on most systems.

| Port 8080 free
| `lab-serve` binds to `localhost:8080`.

| `curl`
| Required by `lab-check-updates`. Pre-installed on all platforms.

| Linux/amd64 emulation
| The Antora container runs as `--platform linux/amd64`. On Apple Silicon Macs, enable Rosetta in Docker Desktop settings or run `podman machine init --arch amd64`.
|===

=== Running the preview

[source,bash]
----
# Build the Antora site and extract the nookbag UI shell
utilities/lab-build

# Start the local HTTP server
utilities/lab-serve

# Browse to http://localhost:8080/index.html
----

The iterative cycle is: edit a file → run `utilities/lab-build` → refresh the browser.

[source,bash]
----
# Stop the server when done
utilities/lab-stop

# Remove the build output to start clean
utilities/lab-clean
----

[NOTE]
====
`lab-build` caches the nookbag UI zip at `/tmp/nookbag.zip`.
If you see UI issues after an upgrade, delete `/tmp/nookbag.zip` and run `lab-build` again.
====

=== Alternative: GitHub Pages

The repo includes `.github/workflows/deploy-pages.yml`.
It runs `utilities/lab-build` on every push to `main` and deploys to GitHub Pages —
useful for sharing a live preview URL with collaborators without any local setup.

To enable: go to your repo → *Settings* → *Pages* → set *Source* to *GitHub Actions*, then push to `main`.

== Development workflow

The modules in this template follow the natural build order for a new lab:

. Define your VMs, networks, and firewall rules (`config/`)
. Write provisioning scripts (`setup-automation/`)
. Define your modules and tabs (`ui-config.yml`)
. Write solve and validation scripts (`runtime-automation/`)
. Write instruction pages (`content/`)
. Tag a release and publish via AgnosticV
