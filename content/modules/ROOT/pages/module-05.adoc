= Runtime automation

`runtime-automation/` contains scripts that run during the lab *as you move through the modules*.
Unlike `setup-automation/` (which runs once at provisioning), these scripts run on each UI action you take.

This module is a *live demo* — the terminal tab is connected to your lab VM.
Complete the task below, then click *Next* to see validation in action.

== The three stages

Each UI action maps to a stage:

[cols="1,2,2"]
|===
| Stage | When it runs | Script name

| `setup`
| When you *enter a module* or click *Next* (after validation passes)
| `setup-<vmname>.sh`

| `validation`
| When you click *Next* — runs before advancing
| `validation-<vmname>.sh`

| `solve`
| When you click the *Solve* button — the button is shown only when `solveButton: true` on that module in `ui-config.yml`
| `solve-<vmname>.sh` (optional — if missing, clicking *Solve* is a no-op)
|===

[IMPORTANT]
====
A `validation-<vmname>.sh` that exits with a *non-zero exit code* blocks you from advancing.
Use this to verify that the lab task has actually been completed.
====

== Script naming and directory structure

Scripts live in `runtime-automation/<module-dir>/` and follow the pattern `<stage>-<vmname>.sh`:

[source,shell]
----
runtime-automation/
├── main.yml                            # Platform entry point — do not modify
├── inventory                           # Platform-managed — do not modify
├── module-01/
│   ├── setup-host1.sh                  # Runs when you enter module-01
│   ├── solve-host1.sh                  # Runs when you click Solve
│   └── validation-host1.sh            # Runs when you click Next
├── module-05/
│   ├── setup-host1.sh                  # This module's demo scripts
│   ├── solve-host1.sh
│   └── validation-host1.sh
└── ansible.cfg
----

If no script exists for a VM/stage combination, nothing runs — no error.
For `solve`, you can set `solveButton: true` to expose the button even when you omit `solve-<vmname>.sh` (useful when the button is decorative or you add the script later).

== Injected variables

[cols="1,3"]
|===
| Variable | Description

| `module_dir`
| Directory name of the active module (e.g. `module-05`)

| `module_stage`
| The event: `setup`, `solve`, or `validation`

| `ansible_host`
| VM hostname — matches the VM name in `instances.yaml` (e.g. `host1`)

| `GUID`
| Lab GUID (same value as `+{guid}+` in `.adoc` pages)

| `common_password`
| Lab user password
|===

== This module's demo scripts

When you entered this module, `setup-host1.sh` ran and cleaned the demo state.
When you click *Next*, `validation-host1.sh` will run and check for a file.
If you click *Solve*, `solve-host1.sh` creates the file on your behalf.

Here are all three scripts:

.`runtime-automation/module-05/setup-host1.sh`
[source,bash]
----
#!/bin/sh
# Runs when you enter module-05. Resets state so the demo is repeatable.
rm -f /tmp/lab-complete
echo "module-05 ready" >> /tmp/progress.log
----

.`runtime-automation/module-05/validation-host1.sh`
[source,bash]
----
#!/bin/sh
# Runs when you click Next. Non-zero exit code blocks progression.
if [ -f /tmp/lab-complete ]; then
  echo "Validation passed" >> /tmp/progress.log
  exit 0
else
  echo "Validation failed: /tmp/lab-complete not found" >> /tmp/progress.log
  exit 1
fi
----

.`runtime-automation/module-05/solve-host1.sh`
[source,bash]
----
#!/bin/sh
# Runs when you click Solve. Creates the file on your behalf.
touch /tmp/lab-complete
echo "Solved: created /tmp/lab-complete" >> /tmp/progress.log
----

== Your task

In the terminal tab, run:

[source,bash]
----
touch /tmp/lab-complete
----

Then click *Next*. The validation script will find the file and allow you to advance.

If you skip this step and click *Next* directly, the validation will block you with an error.
Click *Solve* to have the platform complete it for you instead.
